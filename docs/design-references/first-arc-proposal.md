# First arc — Aevia proposal
Created: 2026-10-11
Modified: 2026-10-11

## Empty state and general creation
Created: 2026-10-11
Modified: 2026-10-11

Lion identifies the need to create the first arc before authoring records within it. Proposed behavior: an empty application offers **Create an arc**. The same action remains available after arcs exist, allowing independent arcs to be created without a transition from another arc. The exact placement in a browser or application menu is open.

## Creation draft
Created: 2026-10-11
Modified: 2026-10-11

Use a small form with a title, narrative description, beginning information, and ending information or ongoing status. Generate a stable UUID automatically; the editable name is a separate label and may be suggested from the title. Unknown temporal information should be allowed and preserved through ChronoMark-compatible representation. Required fields beyond identity have not yet been agreed; Aevia proposes requiring a title for practical browsing and allowing the description and dates to be filled later.

A first arc should not require a predecessor, parent arc, or separately created boundary event. If an arc began long ago, creating its database record today must not imply that its real-life beginning was today. Historical arcs can be created with endings as well as ongoing arcs.

## After saving
Created: 2026-10-11
Modified: 2026-10-11

Save persists the arc and opens its Arc Detail View. An empty chronology offers the journal-entry and event actions from [the authoring proposal](arc-authoring-proposal.md). This establishes an initial path from no data to a readable arc with associated records.
